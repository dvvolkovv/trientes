# Удаление компаний и точек приёма: мягко, с мультиподписью для сотрудников (Слайс G2)

**Дата:** 2026-11-06
**Раздел:** кабинет компании `/{locale}/cabinet/companies/[id]`; кабинет
`/{locale}/cabinet#companies`; админская очередь `/{locale}/admin/business`

## Контекст

После слайса G1 один аккаунт владеет сколькими угодно компаниями и заводит точки
от имени любой из них. Обратного действия нет вообще: ни компанию, ни точку
удалить нельзя — ни владельцу, ни админу. Ошибочно созданная компания висит в
кабинете навсегда, закрытый магазин остаётся на карте.

## Решения владельца (подтверждены 2026-11-06)

1. **Кто удаляет без голосования.** Владелец компании (`OWNER`) удаляет сам.
   Сотрудник с правом редактирования (`EDITOR`) удалить не может — только
   запросить; запрос подтверждают владельцы. `VIEWER` не может ни того, ни
   другого. Админ сайта удаляет всегда, из админки, с записью в `AdminAuditLog`.
2. **Удаление мягкое.** Одним механизмом `deletedAt` и для компании, и для
   точки. Жёсткий каскад снёс бы точки, членства, приглашения и KYB-документы и
   оставил бы висячие `targetId` в журнале админа.
3. **Мультиподпись узкая.** Не конвейер ревизий как у карточек монет, а одна
   модель запроса на удаление. Порог — все владельцы компании, кроме заявителя;
   при одном владельце это вырождается в «владелец подтвердил».

## Принципы

1. **Удалённое исчезает везде, где его читают.** Не «пропадает со страницы», а
   выпадает из всех выборок: публичных, кабинетных, админских, поиска, карты,
   счётчика приёма, карты сайта. Полумера здесь — утечка.
2. **Восстановление возможно, но не в этом слайсе.** Данные остаются в базе, и
   это сознательно: ошибочное удаление должно быть обратимо руками админа через
   базу, пока нет интерфейса восстановления.
3. **Голосование считается по снимку.** Порог фиксируется на момент подачи
   запроса. Иначе уход или добавление владельца на ходу меняет исход идущего
   голосования.
4. **Протухший запрос — не висящий запрос.** Через 14 дней без решения запрос
   истекает, как и ревизия карточки.
5. **Максимальный реюз.** Арифметика голосов у нас уже есть
   (`tally`/`thresholdReachable` в `coin-card-multisig.ts`) — она выносится в
   общий `src/lib/multisig.ts` и используется обеими подсистемами, а не
   копируется.

## Данные

```prisma
model Company {
  // ...существующие поля...
  deletedAt   DateTime?
  deletedById String?
  @@index([deletedAt])
}

model CompanyPoint {
  // ...существующие поля...
  deletedAt   DateTime?
  deletedById String?
  @@index([deletedAt])
}

enum CompanyDeletionKind { COMPANY POINT }
enum CompanyDeletionStatus { PENDING APPLIED REJECTED WITHDRAWN EXPIRED }
enum CompanyDeletionVote { APPROVE REJECT }

// Узкая мультиподпись: только про удаление, только голосами владельцев.
model CompanyDeletionRequest {
  id            String                @id @default(cuid())
  companyId     String
  company       Company               @relation(...)
  kind          CompanyDeletionKind
  pointId       String?               // только при kind = POINT
  requestedById String
  reason        String?               // до 500 символов
  status        CompanyDeletionStatus @default(PENDING)
  thresholdAt   Int                   // снимок: сколько подтверждений нужно
  ownerCountAt  Int                   // снимок состава владельцев
  expiresAt     DateTime
  decidedAt     DateTime?
  createdAt     DateTime              @default(now())
  approvals     CompanyDeletionApproval[]
}

model CompanyDeletionApproval {
  id        String              @id @default(cuid())
  requestId String
  userId    String
  vote      CompanyDeletionVote
  createdAt DateTime            @default(now())
  @@unique([requestId, userId])   // один голос на владельца
}
```

`AdminAction` дополняется значениями `DELETE_COMPANY` и `DELETE_POINT`.

## Маршрутизация удаления

Чистая функция `routeDeletion({ role, isSiteAdmin, ownerCount })`:

| Кто | Результат |
| --- | --- |
| админ сайта | `apply` — удаляет сразу, запись в `AdminAuditLog` |
| `OWNER` | `apply` — удаляет сразу |
| `EDITOR` | `request` — создаётся запрос, порог = число владельцев |
| `VIEWER`, не член | `forbidden` |

Порог: `deletionThreshold({ ownerCount, requesterIsOwner })` = число владельцев
минус заявитель, но не меньше одного. Заявитель-`EDITOR` не владелец, поэтому
порог равен числу владельцев; при одном владельце порог равен единице.

Исход считает общий `tally({ thresholdAt, signerCountAt, approvals, rejections })`:
`PASSED` → удаление применяется той же транзакцией, `FAILED` → запрос
`REJECTED`, иначе `WAITING`.

## Что именно значит «удалено»

- **Точка:** `deletedAt` проставлен. Выпадает из POI-фида, поиска по точкам,
  счётчика приёма на карточке монеты, списка точек в кабинете, админской очереди
  и каталога `/services`.
- **Компания:** `deletedAt` проставлен. Выпадает из списка компаний кабинета,
  публичного каталога `/companies`, публичной страницы компании, поиска,
  `sitemap.xml`, админской очереди. **Её точки считаются удалёнными вместе с
  ней** — не проставлением `deletedAt` каждой (это переписывание истории), а
  условием в выборках: точка видна, только если её компания не удалена. Это уже
  так устроено для статуса компании в `fetchApprovedPointsInBbox`.
- Членства, приглашения и KYB-документы остаются в базе и недоступны, потому что
  доступ к ним идёт через компанию.
- Повторное удаление уже удалённого — ошибка `already_deleted`, а не тихий
  успех.
- Карточка монеты, у которой `companyId` указывал на удалённую компанию, не
  ломается: связь уже `onDelete: SetNull`, а при мягком удалении поле просто
  перестаёт использоваться для отображения.

## Где применяется фильтр

Один источник истины — `src/lib/soft-delete.ts`:

```ts
export const NOT_DELETED = { deletedAt: null };
/** Точка видна, только если и она, и её компания живы. */
export const LIVE_POINT = { deletedAt: null, company: { deletedAt: null } };
```

Фрагменты подмешиваются во все выборки: `business.ts`, `company-points.ts`,
`coin-card-acceptance.ts`, `coin-card-merchant-viewer.ts`, `companies/page.tsx`,
`companies/[id]/page.tsx` и его `opengraph-image`, `services/page.tsx`,
`admin/business/page.tsx`, `cabinet/companies/[id]/page.tsx`, `api/search`,
`sitemap.ts`, `actions/company.ts`, `actions/company-members.ts`,
`actions/kyb.ts`, `actions/admin-company.ts`, `actions/admin-points.ts`.

## Интерфейс

- **Кабинет компании:** у каждой точки кнопка удаления; у компании — кнопка в
  конце страницы, с подтверждением вводом отображаемого названия (защита от
  случайного клика). Для `EDITOR` обе кнопки называются «Запросить удаление».
- **Раздел «Запросы на удаление»** появляется в карточке компании, когда есть
  хотя бы один `PENDING`: кто, что, когда, причина, кнопки «Подтвердить» и
  «Отклонить» для владельцев, «Отозвать» для заявителя.
- **Админка:** в очереди бизнеса у компании и точки кнопка «Удалить» с
  обязательной причиной (≥3 символа, как у отклонения).
- **Уведомления:** владельцам — о новом запросе и о применённом удалении
  (`notifyUser`, как в командных аккаунтах).

## Воркер

`expireStaleDeletionRequests(prismaLike, now)` по образцу
`expireStaleRevisions`: `PENDING` + `expiresAt < now` → `EXPIRED`. Вызывается
там же, где истечение ревизий карточек.

## Ошибки и валидация

`not_found`, `forbidden`, `already_deleted`, `last_owner_company` (владелец не
может удалить компанию, если он единственный владелец и есть другие члены —
иначе люди остаются в компании без владельца; сначала передайте владение или
удалите членов), `reason_too_long`, `request_exists` (один `PENDING`-запрос на
объект), `already_voted`, `not_pending`, `reason_required` (для админа).

## Тестирование

Чистыми функциями, без базы:
- `routeDeletion` — все четыре роли и админ сайта;
- `deletionThreshold` — один владелец, три владельца, заявитель-владелец;
- `tally` — уже покрыт, добавляется проверка переиспользования из `multisig.ts`;
- `expireStaleDeletionRequests` на `PrismaLike`;
- `LIVE_POINT`/`NOT_DELETED` — тест, что фрагмент содержит ожидаемую форму
  (защита от опечатки в ключе).

Интеграционно: удалённая точка исчезает из POI-фида и из счётчика приёма
немедленно; удалённая компания уносит свои точки из фида, не трогая их записи.

## Границы слайса

**Входит:** мягкое удаление компании и точки, маршрутизация по роли, узкая
мультиподпись для сотрудника, фильтр во всех читающих выборках, интерфейс в
кабинете и админке, истечение запросов, уведомления.

**Не входит:** интерфейс восстановления удалённого (обратимо через базу),
удаление карточек монет и финтех-сервисов, передача владения компанией,
физическое удаление данных и сроки хранения.
