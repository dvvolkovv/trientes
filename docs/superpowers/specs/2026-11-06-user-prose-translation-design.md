# Перевод пользовательской прозы: карточка монеты, компании, финтех (Слайс H)

**Дата:** 2026-11-06
**Раздел:** `/{locale}/coin/[slug]` (собственная карточка), `/{locale}/companies/[id]`,
`/{locale}/fintech/[slug]`

## Контекст

Машинный перевод в проекте есть (`src/lib/coin-description.ts` + `translate.ts`,
кеш в Redis на 30 дней), но подключён ровно к одному полю — `Coin.description`
из фида CoinGecko. Текст **собственной** карточки монеты через него не проходит:
что проект ввёл, то и рендерится во всех десяти локалях.

Это видно на живом примере. Вся проза карточки Taler введена по-русски, и
русский текст получают немецкая, японская и английская версии страницы.

Вторая, менее очевидная половина проблемы: существующий механизм считает
английский языком источника и отдаёт его насквозь без перевода
(`if (locale === "en") return englishHtml`). Для собственных карточек это
неверно — источником может быть любой язык, поэтому **английскую** версию тоже
надо переводить.

## Принципы

1. **Переводим прозу, не данные.** Названия, тикеры, имена сетей, адреса
   контрактов, ссылки и числа остаются как есть: их «перевод» — порча данных.
2. **Перевод помечен как перевод.** На этой карточке каждое значение говорит,
   откуда взято. Машинный перевод заявления проекта — производный текст, а не
   само заявление, и подменять одно другим молча нельзя. Рядом — доступ к
   оригиналу.
3. **Один вызов на карточку и локаль, а не на поле.** Вся проза собирается в
   один объект и переводится одним запросом. Иначе шесть полей дают шесть
   вызовов и шесть кешей на каждую локаль.
4. **Язык источника — явное знание, а не догадка на каждый запрос.** Он
   определяется один раз и хранится.
5. **Отказ перевода не ломает страницу.** Нет ключа, таймаут, сбой модели —
   показывается оригинал, как и сейчас в `localizedDescription`.
6. **Механизм общий.** Та же проза у компаний, точек приёма и финтех-сервисов,
   поэтому библиотека не знает про монеты.

## Что переводится

**Карточка монеты:** `tagline`, `description`, `marketing.pitch`,
`tokenomics.emission`, `tokenomics.burn`, `tokenomics.methodology`.

**Компания:** `description`. **Финтех-сервис:** `description`, `feesSummary`.

Не переводится: `name`, `symbol`, `legalName`, `displayName`, `consensus`,
`hashAlgo`, имена сетей и бирж, все URL, все числа, `security.jurisdiction`
(код/название юрисдикции), `security.legalEntity` (имя юрлица).

## Данные

```prisma
model CoinCard {
  // ...
  // Язык, на котором проект ввёл текст. Пусто → определяется один раз
  // автоматически при первом публичном рендере и сохраняется.
  sourceLocale String?
}
```

Компания и финтех поля не получают: их `sourceLocale` определяется и кешируется
в Redis по хешу текста — для одного поля отдельная колонка не нужна, а схему
двух таблиц ради этого менять дороже, чем польза.

## Механизм

`src/lib/localized-prose.ts` (новый, общий):

```ts
/** Перевод набора строк в локаль интерфейса. Ключ кеша — хеш исходного набора,
 *  поэтому правка текста автоматически обесценивает старый перевод. */
export async function localizedProse(input: {
  ns: string;                       // "card" | "company" | "fintech"
  id: string;
  locale: string;
  sourceLocale: string | null;      // null → определить
  fields: Record<string, string | null>;
}): Promise<{ fields: Record<string, string | null>; translated: boolean; sourceLocale: string | null }>
```

- пустой набор, `sourceLocale === locale` или неподдерживаемая локаль → оригинал
  и `translated: false`;
- кеш `i18nprose:{ns}:{id}:{locale}:{hash}` на 30 дней;
- промах → запускается перевод (он сам кладёт в кеш) с мягким дедлайном 8 секунд,
  как в `localizedDescription`; не успел — отдаётся оригинал, следующий рендер
  получит кеш;
- `targetLanguageName` дополняется английским: источник может быть не английским.

В `translate.ts` добавляется `translateStrings(obj, lang)` — перевод значений
JSON-объекта одним запросом с сохранением ключей, и `detectSourceLocale(text)` —
определение языка одним запросом, с ответом строго из списка наших локалей.

**Почему не `translateHtml`.** Проза карточки хранится как обычный текст
(рендерится через `whitespace-pre-line`, а не `dangerouslySetInnerHTML` — это
защита от stored XSS). Промпт `translateHtml` требует сохранять теги и на чистом
тексте провоцирует модель вернуть разметку.

## Интерфейс

- Переведённые блоки получают маркер «машинный перевод» рядом с заголовком —
  в том же визуальном языке, что `ProvenanceBadge`, без новых цветов и форм.
- Рядом ссылка «оригинал» → та же страница с `?orig=1`, которая отключает
  перевод. Параметр не влияет ни на что, кроме прозы.
- Маркер не ставится, когда перевод не делался (локаль совпала с источником или
  модель не ответила) — иначе он врал бы.

## Ошибки и валидация

`sourceLocale` принимается только из списка поддерживаемых локалей, иначе
отбрасывается в `null` (`source_locale_invalid` в редакторе секции IDENTITY).
Отказ перевода ошибкой пользователю не считается — это тихая деградация до
оригинала.

## Тестирование

Чистыми функциями, без сети:
- сбор набора прозы из карточки: пустые и отсутствующие поля отбрасываются,
  числа и URL не попадают;
- ключ кеша меняется при правке любого поля набора;
- `sourceLocale === locale` → перевод не запускается вовсе;
- неподдерживаемая локаль → оригинал;
- слияние перевода обратно в карточку не теряет непереведённые поля и не меняет
  их порядок;
- валидация `sourceLocale`: `"ru"` принимается, `"klingon"` отбрасывается.

## Границы слайса

**Входит:** общая библиотека, карточка монеты, компания, финтех-сервис, маркер
перевода и доступ к оригиналу, поле `sourceLocale` с автоопределением.

**Не входит:** перевод названий точек приёма (это имена собственные), ручной
выбор языка источника в визарде создания карточки (поле редактируется в секции
IDENTITY после создания), перевод отзывов и переписки, человеческая вычитка
машинного перевода, перевод при выдаче API.
