# Доказательство владения карточкой (Слайс D)

**Дата:** 2026-11-07
**Раздел:** `/{locale}/coin/[slug]` (плашка доверия и история); кабинет карточки
`/{locale}/cabinet/coins/[id]` (секция «Подтверждение владения»); воркер

## Контекст

Слайс A сознательно отдал карточку первому подавшему — куратору — и оставил
`trust = UNVERIFIED` с публичной плашкой «ведётся сообществом, проект не
подтвердил причастность». Передача владения до сих пор делается **админом
руками** (`transferCoinCard` в `src/app/actions/admin-coin-revisions.ts`), то
есть упирается в человека и в доверие к нему.

Это слайс, который убирает человека из середины: проект доказывает контроль
машинно проверяемым способом, и `trust` поднимается сам. Для нас это ещё и
защита от сквоттинга наоборот: пока доказательства нет, карточку нельзя
«продать», а когда оно есть — куратор не может удержать карточку против проекта.

## Принципы

1. **Доказательство — то, что может предъявить только владелец.** Подпись
   приватным ключом владельца контракта, запись в DNS домена, файл на сервере
   домена. Скриншот, письмо «от нас» и слово куратора доказательствами не являются.
2. **Проверяем мы, а не верим админу.** Админский перенос остаётся как ручная
   отмычка на крайний случай и как и прежде пишется в публичный аудит; обычный
   путь — автоматическая проверка.
3. **Одноразовый вызов, привязанный к карточке и заявителю.** Токен нельзя
   переиспользовать на другой карточке и нельзя предъявить от чужого имени.
4. **Куратор не исчезает молча.** При успешном claim он понижается до `EDITOR`,
   а не удаляется, событие пишется в публичную историю карточки, обоим уходит
   уведомление. Дальше решает проект.
5. **Ключей не нужно.** DNS читается через DNS-over-HTTPS (Cloudflare, резерв —
   Google), файл домена — обычным GET, подпись — локально. Ни одного платного API.
6. **Отказ объясняется.** «Не сошлось» — это всегда конкретный код: запись не
   найдена, подпись не того адреса, у контракта нет владельца, домен не совпал с
   сайтом карточки.

## Три способа доказать

| Способ | Что делает проект | Что проверяем |
| ------ | ----------------- | ------------- |
| `OWNER_SIGNATURE` | подписывает текст вызова ключом адреса-владельца токена (MetaMask → «Sign message») | EIP-191 `personal_sign`: восстанавливаем адрес из подписи и сверяем с `owner()` канонического контракта, прочитанным через RPC слайса B |
| `DNS_TXT` | добавляет TXT-запись `trientes-verification=<токен>` на домен сайта карточки | DoH-запрос TXT по домену; совпадение хотя бы одной записи |
| `WELL_KNOWN` | кладёт файл `https://<домен>/.well-known/trientes-verification.txt` с токеном внутри | GET файла, точное совпадение токена в теле (≤1 КБ) |

Домен берётся из `links.website` карточки: доказательство на чужом домене не
доказательство. Подпись доступна только когда у канонического контракта есть
`owner()` — слайс B уже умеет видеть флаг `OWNED`; если владельца нет, способ
честно недоступен (`no_owner`), остаются DNS и файл.

**Почему не «пост с официального аккаунта»**, как было в роадмапе слайса A:
X закрыл бесплатное чтение, проверка поста требует платного ключа и всё равно
не машинна (аккаунт можно переименовать). Файл на `/.well-known/` даёт то же
«мы контролируем официальный канал проекта», но проверяется без ключей и
воспроизводимо. GitHub как четвёртый способ — отдельный мелкий шаг позже, код
проверки у `WELL_KNOWN` и у «файла в репозитории» один и тот же.

## Данные (одна аддитивная миграция)

```prisma
enum ClaimMethod {
  OWNER_SIGNATURE
  DNS_TXT
  WELL_KNOWN
}

enum ClaimStatus {
  PENDING    // вызов выдан, доказательство ещё не сошлось
  VERIFIED   // сошлось, владение передано
  FAILED     // исчерпаны попытки
  EXPIRED    // 14 дней вышли
  CANCELLED  // заявитель отменил
}

model CoinCardClaim {
  id          String      @id @default(cuid())
  cardId      String
  card        CoinCard    @relation(fields: [cardId], references: [id], onDelete: Cascade)
  claimantId  String
  claimant    User        @relation(fields: [claimantId], references: [id], onDelete: Cascade)
  method      ClaimMethod
  status      ClaimStatus @default(PENDING)
  /** Токен вызова: показывается заявителю, ищется в DNS/файле, входит в текст подписи. */
  token       String      @unique
  /** Домен (DNS/файл) или адрес владельца (подпись) — что именно проверяли. */
  target      String?
  attempts    Int         @default(0)
  lastError   String?
  lastTriedAt DateTime?
  verifiedAt  DateTime?
  expiresAt   DateTime
  createdAt   DateTime    @default(now())

  @@index([cardId, status])
  @@index([claimantId, createdAt])
}
```

Отдельная модель, а не поля в `CoinCard`: заявок на одну карточку бывает
несколько (разные способы, разные люди), и попытки с ошибками — это журнал, а
не свойство монеты.

## Текст подписи

```
Trientes card ownership claim
card: <slug>
claimant: <username>
token: <токен>
```

Подписывается как есть, через `personal_sign` (EIP-191: префикс
`\x19Ethereum Signed Message:\n<len>`). Токен внутри текста — поэтому чужую
подпись нельзя переставить на другую карточку, а подпись с другой карточки не
подойдёт к этой.

## Проверка подписи

`eth_sign`-совместимое восстановление адреса: `keccak256` префиксованного
сообщения, `secp256k1.recover(sig, hash, v)`, адрес = последние 20 байт
`keccak256(pubkey[1..])`. Берём `@noble/secp256k1` и `@noble/hashes` — крошечные
проверенные библиотеки без зависимостей; тянуть `ethers` или `viem` ради одной
функции незачем. (Слайс B обошёлся без keccak, захардкодив селекторы; здесь
keccak нужен по существу.)

Восстановленный адрес сверяется с `owner()` канонического контракта, который
читается тут же через `ethCall` из `src/lib/evm-rpc.ts`. Регистр не важен,
сравнение по нижнему регистру.

## Что происходит при успехе

Одной транзакцией:

1. `CoinCardClaim.status = VERIFIED`, `verifiedAt = now`.
2. Заявитель — `CoinCardMember{role: OWNER, isSigner: true}` (upsert).
3. Прежний куратор, если это другой человек, — `role = EDITOR`.
4. `CoinCard.stewardUserId = заявитель`, `trust` поднимается:
   `PROJECT_CLAIMED`, а если контракт уже сверен слайсом B
   (`verifiedAt != null` у канонического) — сразу `FULLY_VERIFIED`.
5. Запись в `AdminAuditLog` — `TRANSFER_COIN_CARD` с `actorId = заявитель` и
   `details.method`: публичная история карточки уже умеет это показывать.
6. Уведомления (`notifyUser`): новому владельцу — «карточка ваша», прежнему
   куратору — «владение передано подтверждённому проекту».

Остальные `PENDING`-заявки на эту карточку закрываются как `CANCELLED`:
доказательство уже предъявлено.

## Лимиты и защита

- ≤3 активных (`PENDING`) заявок на пользователя, ≤3 на карточку.
- ≤10 попыток проверки на заявку (`attempts`), дальше `FAILED`.
- Проверка не чаще раза в 60 секунд на заявку (`lastTriedAt`) — DNS и чужой
  сайт не должны страдать от кнопки «проверить».
- Срок жизни вызова — 14 дней; просроченные гасит воркер (`EXPIRED`).
- Токен — 32 байта из `crypto.randomUUID()`-класса источника, в виде
  `trientes-<hex40>`; ищется в TXT и в файле как подстрока целиком.
- Домен нормализуется из `links.website` (хост без `www.`, нижний регистр);
  заявка без сайта у карточки — `no_website`.
- Карточка со `trust = PROJECT_CLAIMED` или `FULLY_VERIFIED` новых заявок не
  принимает (`already_claimed`) — иначе доказавший проект можно было бы
  перебить второй заявкой.

## Кадансы

- Воркер: `runClaimSweep()` раз в час (`20 * * * *`) — помечает `EXPIRED`
  просроченные `PENDING`-заявки. Автоповтора проверки нет сознательно: DNS и
  файл появляются по действию человека, и этот человек нажмёт кнопку сам.
- Проверка — по кнопке в кабинете карточки.

## Как это видно

**Кабинет карточки, секция «Подтверждение владения»:** выбор способа,
инструкция под каждый (что именно вставить в DNS / какой файл положить / какой
текст подписать), поле для подписи (для `OWNER_SIGNATURE`), кнопка «Проверить»,
счётчик попыток и последняя ошибка человеческим языком, срок действия вызова.
Видна владельцу карточки и тому, кто подал заявку.

**Публичная карточка:** плашка доверия меняется сама (`PROJECT_CLAIMED` →
«проект подтвердил владение карточкой»); в публичной истории появляется строка
о передаче владения с указанием способа.

## Ошибки

`unauth`, `card_not_found`, `already_claimed`, `no_website`, `no_contracts`,
`no_owner` (у контракта нет `owner()`), `too_many_claims`, `claim_not_found`,
`claim_closed`, `too_soon`, `attempts_exhausted`, `signature_invalid`,
`signature_wrong_address`, `dns_no_record`, `dns_unreachable`,
`well_known_missing`, `well_known_unreachable`, `token_not_found`.

## Тестирование

Чистыми функциями, без сети и базы:
- текст вызова: детерминирован, токен внутри;
- восстановление адреса: подпись, сделанная тестовым ключом, даёт его адрес;
  испорченная подпись → `signature_invalid`; подпись другого ключа →
  `signature_wrong_address`; `v` в обоих видах (27/28 и 0/1);
- нормализация домена: `https://www.Example.com/path` → `example.com`,
  мусор → null;
- разбор ответа DoH: запись есть, записи нет, несколько записей, запись с
  кавычками, ответ с ошибкой;
- разбор файла `.well-known`: токен в теле, токен с пробелами и переводами
  строк, чужой токен, тело больше килобайта;
- правила перехода: `PROJECT_CLAIMED` против `FULLY_VERIFIED` в зависимости от
  сверки контракта; лимиты попыток и окно 60 с; `already_claimed`.

С подменённым `fetch` — DNS-over-HTTPS и файл: таймаут, 404, 500, резервный
резолвер.

Интеграционно (с базой): две заявки на одну карточку, успех одной закрывает
вторую; гонка двух проверок одной заявки (условный `updateMany` по
`status: "PENDING"`, как в `company-invites.ts`).

## Границы слайса

**Входит:** модель заявки, три способа доказательства, проверка подписи,
DoH-резолвер, чтение файла домена, передача владения с понижением куратора,
подъём `trust`, аудит и уведомления, лимиты, воркер-гаситель, секция в кабинете,
смена плашки на публичной карточке, 10 локалей.

**Не входит:** привязка подписантов мультисига к адресам кошельков и чтение
порога из настоящего Gnosis Safe (заявлено как возможное развитие в слайсе A —
отдельный слайс), подтверждение через GitHub и соцсети, проверка подписи
не-EVM сетей (Solana `ed25519`, TON), KYB-верификация проекта, отзыв
подтверждения (делается админом вручную, как и прежде).
