# Собственный агрегатор рынков и ценовой индекс (Слайс C)

**Дата:** 2026-11-07
**Раздел:** публичная карточка `/{locale}/coin/[slug]` (шапка + секция `#markets`);
кабинет карточки `/{locale}/cabinet/coins/[id]`; листинг самостоятельных карточек;
воркер

## Контекст

После A1/A2/B/F карточка знает, что заявил проект, и умеет сверять контракт с
сетью. Рынки остались полностью на слове проекта: `CoinCardMarket.priceUsd`
существует с миграции A1 и всегда `null`, `confirmedAt` — тоже. На публичной
карточке колонка цены сознательно скрыта (`markets-section.tsx`), а
самостоятельно залистингованные монеты в листинге идут без цены и капитализации
(`coin-card-directory.ts`) — им неоткуда её взять: CoinGecko их не знает и знать
не будет.

Это слайс, который закрывает дыру: цена новой монеты считается нами, из
публичных API бирж, без ключей и без посредника. Заодно появляется проверка
самого заявления о листинге — «на этой бирже такой пары нет» это второй по
важности сигнал скама после «по этому адресу нет контракта».

## Принципы

1. **Индекс устойчив к накрученному объёму.** Не VWAP, а **медиана по весу
   объёма**: цена, на которой накопленный объём переваливает за половину. Чтобы
   сдвинуть VWAP, достаточно одной биржи с фиктивным оборотом; чтобы сдвинуть
   взвешенную медиану, фиктивным должно быть больше половины всего объёма монеты.
2. **Заявление о листинге проверяется так же, как адрес контракта.** Пара,
   которой нет в снимке тикеров биржи, не получает `confirmedAt` и получает
   `checkError = pair_not_found`. Мы не вычёркиваем рынок — мы показываем, что
   не нашли его.
3. **Биржа, которую мы не умеем читать, — честно не прочитана.** Нет в реестре
   коннекторов → `exchange_unsupported`, без притворства. То же решение, что в
   слайсе B для не-EVM сетей.
4. **Отвал биржи не стирает последнюю цену.** `exchange_unreachable` оставляет
   прежние `priceUsd`/`volumeUsd24h` и обновляет только `checkedAt`/`checkError`;
   индекс пересчитывается по тому, что реально ответило, и помечается более
   низкой уверенностью, а не исчезает.
5. **Один снимок на биржу за прогон.** Все коннекторы дают «все тикеры одним
   запросом». Запросов за прогон — по числу бирж, а не по числу рынков; снимок
   кешируется в Redis на 5 минут и переиспользуется ручной кнопкой.
6. **Методика публична.** Рядом с ценой — метка «по N рынкам» и человеческое
   описание метода: какие пары взяты, что отброшено как выброс, какой объём.
   Цена без объяснения, откуда она, — ровно то, что мы критикуем у других.
7. **Ключи не нужны.** Все восемь коннекторов — публичный REST без регистрации,
   базовый адрес переопределяется через `.env` (как RPC в слайсе B).

## Биржи первого набора

| id | Снимок тикеров | Формат символа | Объём |
| -- | -------------- | -------------- | ----- |
| `binance` | `/api/v3/ticker/24hr` | `BASEQUOTE` | `quoteVolume` |
| `okx` | `/api/v5/market/tickers?instType=SPOT` | `BASE-QUOTE` | `volCcy24h` |
| `bybit` | `/v5/market/tickers?category=spot` | `BASEQUOTE` | `turnover24h` |
| `kucoin` | `/api/v1/market/allTickers` | `BASE-QUOTE` | `volValue` |
| `gate` | `/api/v4/spot/tickers` | `BASE_QUOTE` | `quote_volume` |
| `mexc` | `/api/v3/ticker/24hr` | `BASEQUOTE` | `quoteVolume` |
| `kraken` | `/0/public/Ticker` | альтнейм (`XBT` вместо `BTC`) | `v[1] × p[1]` |
| `coinbase` | `/products/stats` | `BASE-QUOTE` | `volume × last` |

Выбор набора: четыре биржи, где фактически появляются новые монеты (MEXC, Gate,
KuCoin, Bybit), и четыре с самым честным объёмом (Binance, OKX, Kraken,
Coinbase). Реестр `src/lib/cex-registry.ts` описывает биржу декларативно
(адрес, парсер, формат символа), добавление девятой — это запись в реестре, а не
новый код в агрегаторе.

Сопоставление с нашей таблицей `Exchange` — по `exchangeId`, если он задан, иначе
по нормализованному `exchangeName` («Binance», «binance», «BINANCE Spot» → `binance`).

## Приведение к доллару

- `USDT USDC USD USDD FDUSD DAI TUSD BUSD PYUSD` = 1 USD. Допущение
  **заявлено прямо в описании методики**, а не спрятано: расхождение стейбла с
  долларом внутри дня меньше разброса цен между биржами, а своего оракула у нас нет.
- `BTC ETH BNB SOL` — котировка переводится в доллар по **нашему же индексу**
  этой монеты, посчитанному в первом проходе по тем же снимкам из стейбл-пар.
- Фиат, кроме USD (`EUR`, `GBP`, `TRY`, `BRL`), — `no_usd_route`. Сознательно:
  тянуть курсы ЦБ в ценовой индекс ради трёх европейских пар — лишняя зависимость,
  а у новых монет таких пар почти нет.

## Математика индекса (`src/lib/price-index.ts`, чистая)

1. Кандидаты — рынки, у которых пара нашлась и объём в долларах известен.
2. Объём < 1 000 $ отбрасывается как пыль (`dust_volume`). Если так отброшены
   **все** — возвращаем их обратно и ставим `confidence = LOW`: цена из пыли
   лучше, чем ничего, но только с явной оговоркой.
3. Предварительная взвешенная медиана по выжившим.
4. Рынки с отклонением > 20 % от неё помечаются `isOutlier` и выходят из расчёта
   (но остаются видимыми в таблице с пометкой «не учтён»).
5. Индекс = взвешенная медиана по оставшимся. `volumeUsd24h` = их сумма,
   `marketCount` = их число, `spreadPct` = (max − min) / индекс.
6. `change24h` — взвешенная медиана суточных изменений тех же рынков (берётся из
   тикеров бирж, а не из нашей истории: история начнётся только сейчас).
7. `confidence`: `HIGH` — ≥ 3 рынка, объём ≥ 100 000 $, разброс ≤ 5 %;
   `LOW` — один рынок, либо разброс > 20 %, либо объём < 10 000 $, либо сработал
   возврат пыли; иначе `MEDIUM`.
8. Ноль кандидатов → индекса нет (`insufficient_markets`), прежняя запись
   сохраняется как устаревшая со своим `computedAt`.

## Данные (одна аддитивная миграция)

```prisma
model CoinCardMarket {
  // ...существующие поля, priceUsd/volumeUsd24h/confirmedAt уже есть с A1...
  nativeSymbol String?    // символ пары на бирже, как он найден в снимке
  quote        String?    // нормализованная котировка (USDT, BTC, ...)
  change24h    Float?
  isOutlier    Boolean    @default(false)
  checkedAt    DateTime?
  checkError   String?
}

model CoinCardPriceIndex {
  id           String   @id @default(cuid())
  cardId       String   @unique
  card         CoinCard @relation(fields: [cardId], references: [id], onDelete: Cascade)
  priceUsd     Float
  change24h    Float?
  volumeUsd24h Float
  marketCount  Int
  spreadPct    Float?
  confidence   String            // HIGH | MEDIUM | LOW
  method       String   @default("VWMEDIAN_V1")
  computedAt   DateTime
}

model CoinCardPricePoint {
  id           String   @id @default(cuid())
  cardId       String
  card         CoinCard @relation(fields: [cardId], references: [id], onDelete: Cascade)
  priceUsd     Float
  volumeUsd24h Float
  marketCount  Int
  at           DateTime
  @@unique([cardId, at])
  @@index([cardId, at])
}
```

`CoinCardPriceIndex` — отдельная модель 1:1, а не поля в `CoinCard`: это
вычисленное значение со своим временем и своей методикой, и его не должны
затрагивать ревизии и диффы карточки (`coin-card-diff.ts` работает по полям
`CoinCard`).

`CoinCardPricePoint` входит в этот слайс, хотя график — нет: **историю нельзя
добрать потом**. Точка пишется не чаще раза в час (с округлением `at` до часа,
отсюда `@@unique`), хранится 90 дней, лишнее подчищает тот же воркер.
`method` строкой, а не enum — смена методики не должна требовать миграции.

## Кадансы

- Воркер: `runCardMarketSync()` каждые 10 минут, `cron.schedule("*/10 * * * *")`.
  Берёт карточки со статусом `APPROVED`, у которых есть хотя бы один рынок на
  бирже из реестра; снимки бирж — из Redis (TTL 5 мин), промах → один запрос на
  биржу. Первым проходом считаются опорные монеты (BTC, ETH, BNB, SOL), вторым —
  карточки. Сбой одной биржи не ломает прогон.
- Чистка истории — раз в сутки, вместе с прогоном в `05 4 * * *`.
- Ручная кнопка в кабинете («Обновить рынки») — тем, кто может править раздел
  `MARKETS`, не чаще раза в 10 минут на карточку (по `CoinCardPriceIndex.computedAt`
  и `checkedAt` рынков), иначе кнопка превращается в бесплатный прокси к биржам.

## Как это видно

**Шапка карточки** (только для карточек без `coinId`, то есть там, где наш
индекс единственный источник):

```
$0.0412   +3.8 % (24 ч)        [по 5 рынкам]
объём 1 240 000 $ · уверенность высокая · 2026-11-07 14:10
```

Метка — существующий `ProvenanceBadge` с `kind = AGGREGATED`, `source = "5"`.
Клик по «по N рынкам» раскрывает описание методики (строка i18n, без нового
дизайна).

**Секция `#markets`:** колонка цены перестаёт быть скрытой; добавляются объём за
сутки и 24 ч; в статусе — «подтверждено» (пара найдена), «не найдено на бирже»
(`pair_not_found`, красным), «биржа не читается» (`exchange_unsupported`,
нейтрально), «не учтён в индексе» (выброс). Пыль — «объём ниже порога».

**Листинг самостоятельных карточек** — цена и 24 ч там, где индекс есть; где нет,
остаётся как сейчас.

**Кабинет** — та же сводка по рынкам, время последнего обновления и кнопка.

## Провенанс

`price` → `{kind: "AGGREGATED", source: "<N>", at: computedAt}`;
`markets` → то же. `mergeProvenance` уже не даёт самозаявлению затереть
`AGGREGATED` (ранг 1 против 0), и не даёт `AGGREGATED` затереть `VERIFIED_ONCHAIN`.

## Ошибки и валидация

Рынок: `exchange_unsupported | pair_unparsable | pair_not_found | base_mismatch |
no_usd_route | dust_volume | exchange_unreachable | exchange_error`.
Индекс: `insufficient_markets`.
Серверное действие: `card_not_found | forbidden | too_soon | no_markets`.

`base_mismatch` — база пары не совпадает с тикером карточки («монета TAL, пара
BTC/USDT»): рынок не подтверждается и в индекс не идёт, иначе чужая цена
подставляется под чужую монету.

## Тестирование

Чистыми функциями, без сети и базы:
- парсеры снимков: по фикстуре на каждую из восьми бирж (нормальный ответ,
  пустой список, мусор в числах → рынок пропущен, а не `NaN` в индексе);
- формат символа и альтнеймы Kraken (`XBT`→`BTC`, `XXBTZUSD`);
- разбор пары: `TAL/USDT`, `tal-usdt`, `TAL_USDT`, `TALUSDT` (по известным
  котировкам), неразбираемое → `pair_unparsable`;
- маршрут к доллару: стейбл, `BTC` через опорный индекс, `EUR` → `no_usd_route`,
  отсутствующий опорный индекс → `no_usd_route`;
- взвешенная медиана: один рынок, два рынка с равным весом, перевес в одну
  биржу, все объёмы нулевые;
- фильтр выбросов: один выброс отброшен, два из трёх — медиана не
  «переезжает» к выбросам;
- вся пыль → возврат с `LOW`;
- `confidence` на границах порогов;
- сверка заявления: пара найдена, пара не найдена, база не та.

Через подменённый `fetch`: таймаут биржи (прежняя цена жива, `checkError`),
HTTP 429, частичный отвал (3 биржи из 8 легли — индекс считается).

## Границы слайса

**Входит:** реестр восьми CEX-коннекторов, снимки тикеров с кешем в Redis,
приведение котировок к доллару, взвешенная медиана с фильтром выбросов,
подтверждение заявленных листингов, запись цены и объёма по рынкам, индекс
карточки, часовая история, провенанс, воркер, ручная кнопка, рендер в шапке, в
секции рынков, в листинге и в кабинете.

**Не входит:** цены DEX-пулов (следующий шаг — чтение резервов Uniswap V2/V3
через RPC слайса B, на базе этого же индекса), глубина стакана и ликвидность,
график цены самостоятельных монет (данные для него начнут собираться сейчас),
капитализация (нужен проверенный circulating supply — пересечение со слайсом E),
замена цены в таблице `Coin` для монет CoinGecko, отключение CoinGecko.
